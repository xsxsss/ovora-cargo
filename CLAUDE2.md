#### Задание для MiMo №4 — дизайн волны 2 (решение владельца: пишет MiMo, проверяет Claude)

Дизайн — это не список проблем (они уже собраны), а **решение**. Чтобы его можно было проверить,
он должен отвечать на всё перечисленное ниже. Без ответа хотя бы на один пункт вернётся.

1. **Одна функция учёта.** Сигнатура помощника, аналога `adjustFlightCapacity` из AVIA: что
   принимает, какие поля меняет, как вызывается на резерв, списание и возврат. Почему именно так.
2. **Полный список точек вызова** — с `file:line` и указанием, что происходит с ёмкостью в каждой:
   создание оффера, принятие, отказ, отмена, отмена отказа, удаление или отмена поездки,
   принятие предложения из чата, админский путь (`/admin/offers/:tripId/:offerId/status`,
   `index.ts:5143` — там возврат уже есть, его надо привести к общей функции), офферы на груз.
   Если точку пропустишь — учёт разъедется, как сейчас.
3. **Защита от гонки.** В KV нет атомарной операции. Опиши, как именно защищаешься: в AVIA это
   запись, перечитывание и сверка `updatedAt`, с повторами. Сколько повторов, что возвращаем,
   если не удалось.
4. **Грузы.** Нужна ли грузу ёмкость вообще или достаточно правила «принят только один оффер»?

##### Как исправить: настоящая условная запись

KV — это таблица Postgres, поэтому атомарная проверка-и-запись возможна одним запросом.
Добавить в `kv_store.tsx`:

```ts
/** Записывает value, только если updatedAt в базе совпадает с expectedUpdatedAt.
 *  Возвращает false, если кто-то успел записать раньше — это сигнал повторить. */
export const setIfUnchanged = async (
  key: string, expectedUpdatedAt: string | null, value: any,
): Promise<boolean> => {
  const supabase = client();
  let q = supabase.from("kv_store_4e36197a").update({ value }).eq("key", key);
  q = expectedUpdatedAt === null
    ? q.is("value->>updatedAt", null)
    : q.eq("value->>updatedAt", expectedUpdatedAt);
  const { data, error } = await q.select("key");
  if (error) throw new Error(error.message);
  return (data?.length ?? 0) > 0;
};
```

`adjustTripCapacity` тогда: прочитать → запомнить `updatedAt` → посчитать → `setIfUnchanged`.
Вернул `false` — повторить цикл (до 3 раз), а не возвращать `CONFLICT_RETRY` наружу.
Проверка достаточности мест должна быть **внутри** цикла, после каждого перечитывания.

Учти: у старых записей `updatedAt` может не быть — поэтому в помощнике предусмотрен вариант
`null` (ветка `is`). Проверь на реальных данных, прежде чем полагаться на это.

статуса груза** замком — `active → matched` через `setIfUnchanged`. Кто перевёл первым, тот и
